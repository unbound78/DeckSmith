# 设计方法论：视觉精修 + 汇报设计

> **这篇是干嘛的**：DeckSmith 的 SKILL.md 给了你「材料 → 框架」的主工作流骨架，但骨架里的每一步——怎么判断信息关系、怎么把逻辑用视觉表达、怎么控制密度和高度、怎么让一份多页材料成为一个有记忆点的故事——都需要**可操作的判断准则**。这篇就是那本判断手册。
>
> **什么时候读**：
> - 做 **Step 3（信息架构）** 判断"这几块信息是什么关系、该用什么结构"时 → 读本文「汇报设计 · 关系图 ≠ 矩阵」+「视觉精修 · 流的表达」+「X→Y 叙事条」。
> - 做 **Step 4（逐页布局）** 判断"这页该长什么样、多页怎么防同质化"时 → 读本文「视觉精修」全部 +「汇报设计 · 内容性格化 4 步法」。
> - 任何多页成体系汇报动手前 → 读「汇报设计 · 宏观叙事骨架」+「总结页三件套」。
> - 每次改完 HTML/PPT，交付前 → 用「1080px 高度预算」+「动画编排」+ Anti-Slop 三张清单自查。
>
> **怎么用**：本文每条都给"怎么判断 / 怎么做"，不是理论。看到一个设计决策拿不准，先在这里找对应准则，再动手。**逻辑凌驾于样子之上——先判断，再选积木或自定义。**

本文分两部分：
- **第一部分 · 视觉精修**：单页/组件级的视觉表达技法（HTML 为主，PPT 通用）。
- **第二部分 · 汇报设计**：整份材料的方法论层（语境、内容、叙事、布局判断）。

# 第一部分 · 视觉精修

## 1. Anti-"AI Slop" 原则（怎么避免一眼 AI 味）

**判断**：一份演示"一眼看上去像 AI 生成"，几乎总是踩中下面这几个默认项。交付前逐条自查，命中任何一条就是 slop。

**不要用（AI 味来源）**：
- ❌ 通用无个性字体：Inter / Roboto / Arial / 系统默认无衬线。
- ❌ 紫色渐变配白底（最典型的"AI 感"配色）。
- ❌ 可预测的通用布局（每页都是标题居中 + 三个等宽卡）。

**要用（去 AI 味）**：
- ✅ **独特字体搭配**：显示字用有性格的衬线/展示体，正文用另一族区分。中文项目务必给中文字形独立兜底（英文展示字体多半不含中文字形，中文标题要 `'中文衬线体', 英文展示体` 的 fallback 顺序，英文字体只吃英文/数字/罗马数字）。
- ✅ **分层背景**：不要纯色。用多层 `radial-gradient` 叠出深度（渐变网格）+ 内联 SVG 噪点做质感（grain overlay）+ 可选细线网格给结构感。**"纯黑/纯白无质感"是 slop 的温床**——底纹双层是标配：一层 mesh 光晕（`::before`）+ 一层 grain 噪点（`::after`）。
- ✅ **上下文特定的设计语言**：设计元素呼应这份材料的主题，而不是套一个万能皮。

**背景三技法（可直接用）**：
- 渐变网格：多层 `radial-gradient(ellipse at 20% 80%)` 叠加 → 深度感。
- 噪声纹理：内联 SVG `fractalNoise` grain overlay（`mix-blend-mode` 暗底用 overlay、亮底用 multiply）→ 触感质感。
- 网格图案：细线 50px 间距 → 结构感。

**技术规范（去 slop 的工程底座）**：
- 每页 `height:100vh; height:100dvh; overflow:hidden`。
- 字号一律 `clamp(2rem, 6vw, 5rem)`，**不用固定 px**（响应式 + 跨屏一致）。
- 间距 `clamp(1.5rem, 4vw, 4rem)`。
- CSS 变量做主题层：`--bg-primary / --text-primary / --accent / --accent-glow`——换配色只改变量，不全局 replace。
- 单文件零依赖，`prefers-reduced-motion` 支持。

**9 项视觉精修技法（有性格的细节，直接沿用）**：
1. 页眉底部分隔线：`::after` 伪元素，`linear-gradient(90deg, var(--border-accent), transparent)`，从左渐隐到右 70%。
2. 封面装饰线框：右上 + 左下各一个 L 形（`border-top + border-right`），opacity 0.5/0.35，增加空间层次。
3. 关键词标签化：圆点+文字 → 带 `border: 1px solid` 的小矩形 + 内部圆点，视觉层级从"点缀"升为"标签"。
4. 侧边竖线：`::before` 伪元素 2px 宽渐变，贴在列表每行左边缘。
5. 大数字发光：`filter: drop-shadow(0 0 30px rgba(accent,0.25))`，给核心数据加聚光灯。
6. 强调边引用条：只有 `border-top` 太弱 → 加 `border-left: 3px solid` + `padding-left`，从"分隔线"变"引用条"。
7. 卡片化 aside：右侧要点区从纯文字改为有 `background + border + border-radius` 的卡片，顶部加 2px hairline。
8. 收尾页装饰圆环：2 个同心 `border-radius:50%` 圆（500px/700px），`border:1px solid rgba(...,0.12/0.06)`，居中绝对定位，给空间感。
9. 收尾大字发光：`filter: drop-shadow(0 0 40px rgba(accent,0.2))`。

**图标选择原则**：用 Unicode 几何符号（⟳ ◈ ◇ ◆ ⊕ ↓ ↗ ⟲ ▲ ⇄ ⚡ ✦）而非 emoji；放进圆形容器（`border-radius:50%` + 低饱和渐变底 + 1px 边框）；圆形 36–60px 按卡片尺寸 `clamp()` 适配。

## 2. 内容密度上限（每种页面类型最多放多少）

**判断**：这是**不可违反**的硬约束。任何一页的内容超出下表，**立刻分页——不挤、不缩到看不清、不加滚动条**。

| 页面类型 | 最大内容 |
|---|---|
| 标题页 | 1 标题 + 1 副标题 + 可选一句标语 |
| 内容页 | 1 标题 + 4–6 条要点，**或** 1 标题 + 2 段落 |
| 卡片网格 | 1 标题 + 最多 6 张卡片 |
| 引用页 | 1 段引用（最多 3 行）+ 署名 |
| 图片页 | 1 标题 + 1 图（最大 60vh） |

**怎么做**：填内容前先数——要点超过 6 条？拆两页。卡片超过 6 张？拆或合并同类。**"信息全"从来不是理由，"一页能吸收"才是标准。**

## 3. "流"的视觉表达方法论（流程/递进怎么用视觉表达）

**触发判断**：当一页是 **N 条工作 / N 个步骤 / N 个动作组成一条完整因果链**时，平铺布局（2×2 / 2×3 网格）只能表达"散点关系"，**表达不了"流"的方向和递进**。如果反馈是"没感受到流的感觉"——这是强信号，要求**视觉表达升级**（不是改文字）。

**叙事 stepper 三层结构**（实测 1080px 装得下 5 步）：

```
┌─────────────────────────────────────────────────────────────┐
│ 顶部 stepper 横条：① 动词 → ② 动词 → ③ 动词 → ④ 动词 → ⑤ 动词 │  ~80–100px
└─────────────────────────────────────────────────────────────┘
┌───────┐ → ┌───────┐ → ┌───────┐ → ┌───────┐ → ┌───────┐
│ 卡 01 │   │ 卡 02 │   │ 卡 03 │   │ 卡 04 │   │ 卡 05 │  ~700px
│ 动词  │   │ 动词  │   │ 动词  │   │ 动词  │   │ 动词  │
│ 主标题│   │ 主标题│   │ 主标题│   │ 主标题│   │ 主标题│
│ 描述  │   │ 描述  │   │ 描述  │   │ 描述  │   │ 描述  │
│ 关键转化   关键转化   关键转化   关键转化   关键转化 │
└───────┘   └───────┘   └───────┘   └───────┘   └───────┘
              ↑（卡间用 ::absolute 圆形边框桥接箭头 →）
┌─────────────────────────────────────────────────────────────┐
│ 底部 summary 渐变条：N 条组成一条完整流动链 → 让 X 从 A 变成 B  │  ~60px
└─────────────────────────────────────────────────────────────┘
```

**3 个关键设计点**：
1. **动词关键化**（每步用 1–2 字强动词，抽象到"语义阶梯"层，而非具体动作描述）——如"调研→设计→试点→扩张→复制"。这是"流"的灵魂：读者看动词横条就能一眼读懂整条链。
2. **卡间桥接箭头**：圆形箭头浮在卡片接缝上，CSS：
   ```css
   .card-bridge {
     position: absolute; right: -0.85rem; top: 50%; transform: translateY(-50%);
     width: 1.7rem; height: 1.7rem; border-radius: 50%;
     background: var(--card); border: 1.5px solid var(--accent);
     display: flex; align-items: center; justify-content: center;
     color: var(--accent); z-index: 10;
     box-shadow: 0 2px 6px rgba(accent,0.18);
   }
   ```
3. **底部 summary 渐变条**：用主题两色渐变 + 文字内嵌 "→" 分隔符，把"流"延续到底，避免戛然而止。

**N 数适配规则**：
- N=3–4：5 列布局留 1–2 列做侧重（最长的步骤放最大的卡）。
- N=5：5 列等宽（每列约 340px @1280 max-width）。
- N=6+：不要一行硬塞，拆 2 页或改纵向时间线 stepper。

**Anti-pattern（什么时候不能用 stepper）**：
- N 条之间**没有先后关系**（并列工作/维度对照）→ 平铺反而对。
- N 条**因果链不清晰**（强行编排动词会错位）→ 用矩阵或卡片墙。

## 4. "X → Y" 叙事条模式（现状→目标 / 问题→转向 / 旧→新）

**用途判断**：在论证型/汇报型页面里表达"现存问题 → 转向"的因果链。**1 行 40–50px 高度装下完整对照**。位置在"理念条之后、数据/卡片之前"，充当"为什么变 → 怎么变"的衔接层。

**HTML 结构**：
```html
<div class="pillar-transition">
  <div class="pt-side issue">
    <div class="pt-label">⚠ 现存</div>
    <div class="pt-text">问题描述 25–35 字</div>
  </div>
  <div class="pt-arrow">→</div>
  <div class="pt-side shift">
    <div class="pt-label">🎯 转向</div>
    <div class="pt-text">转向描述 25–35 字</div>
  </div>
</div>
```

**核心 CSS**：
```css
.pillar-transition {
  display: grid; grid-template-columns: 1fr auto 1fr;
  gap: 1.2rem; align-items: center;
  padding: 0.55rem 1.3rem;
  background: linear-gradient(90deg, rgba(neutral,0.08), rgba(accent,0.12));
  border: 1px solid var(--border); border-radius: 8px;
}
.pt-side { display: flex; flex-direction: row; align-items: baseline; gap: 0.55rem; min-width: 0; }
.pt-label { white-space: nowrap; flex-shrink: 0; font-size: 0.66rem; letter-spacing: 0.18em; text-transform: uppercase; }
.pt-text { flex: 1; min-width: 0; font-size: 0.84rem; line-height: 1.5; }
```

**关键设计（怎么做）**：
1. **横向 row 而非纵向堆叠**：单行比堆叠版省 40–50px（关键容差空间）。
2. **label nowrap + text flex**：标签不换行，描述自适应填充。
3. **色彩编码**：左灰 issue · 中 accent 箭头 · 右双色 shift——视觉编码"问题→解决"。
4. **文本精简 25–35 字**：保留核心动词 + 关键短语 + `<strong>` 高亮。
5. **label 用时间中性词**（"现存"而非"某年暴露"）：覆盖既有问题，无论新出还是长期遗留。

**Anti-pattern（硬约束）**：transition 文本超过 50 字 → 必然换行 → 单行高度被破坏 → 整页重排。**精简到能放一行的字数是硬约束。** 不适用于纯展示型/总结型/封面页。

## 5. CSS 漏斗 + CSS+SVG 飞轮（视觉化转型对比的标准模式）

**用途判断**：命题页要表达"收窄型问题 → 循环型解法"的对比时，需要真"逐层收窄"和真"循环驱动"的视觉，而不是两段文字。

**CSS 漏斗**（3 层梯形堆叠，表达"越往后越窄"）：
```css
.funnel-layer-1 {
  width: 100%;
  clip-path: polygon(0 0, 100% 0, 90% 100%, 10% 100%);
  background: linear-gradient(180deg, rgba(neutral,0.32), rgba(neutral,0.22));
}
.funnel-layer-2 {
  width: 82%; align-self: center;
  clip-path: polygon(7% 0, 93% 0, 83% 100%, 17% 100%);
  background: linear-gradient(180deg, rgba(neutral,0.22), rgba(neutral,0.14));
}
.funnel-layer-3 {
  width: 62%; align-self: center;
  clip-path: polygon(12% 0, 88% 0, 72% 100%, 28% 100%);
  background: linear-gradient(180deg, rgba(neutral,0.14), rgba(neutral,0.08));
}
```
- **关键点**：每层 `width` + `clip-path` **双控收窄**（只靠 clip-path 不够，width 同步缩才显层级）。
- **文本被 clip-path 切的坑**：每层 `padding:0` + flex column 把名称/说明上下堆叠居中，避免左右 padding 把文字推到斜边外被切掉。

**CSS+SVG 飞轮**（4 节点 + 中心圆 + 弧形循环箭头，表达"循环驱动"）：
```html
<div class="flywheel">
  <svg class="fw-svg" viewBox="0 0 280 280">
    <defs>
      <marker id="fw-arr" viewBox="0 0 10 10" refX="6" refY="5"
              markerWidth="7" markerHeight="7" orient="auto">
        <path d="M 0 0 L 10 5 L 0 10 Z" fill="var(--accent)"/>
      </marker>
    </defs>
    <!-- 4 段弧形：top→right / right→bottom / bottom→left / left→top -->
    <path d="M 175 50 A 90 90 0 0 1 230 105" stroke="var(--accent)" stroke-width="2"
          stroke-dasharray="4 3" fill="none" marker-end="url(#fw-arr)" opacity="0.75"/>
    <!-- ...其他 3 段 -->
  </svg>
  <div class="fw-center">中心</div>
  <div class="fw-node top">节点一</div>
  <div class="fw-node right">节点二</div>
  <div class="fw-node bottom">节点三</div>
  <div class="fw-node left">节点四</div>
</div>
```
- **优势**：4 节点用 absolute 占 top/right/bottom/left 四正方向（视觉对称）；SVG 4 段弧形虚线 + marker arrow 制造强循环感；中心圆 + 节点圆层次分明。**比"圆形节点排环 + 平铺标签"信息密度高得多。**
- **记得**：CSS 类名用容器限定（`.flywheel .fw-*`），避免与封面页等其他同名组件冲突（见下方"CSS 类名冲突"）。

## 6. 1080px 高度预算管理（每段高度精算 + 留 buffer）

> 适用于 **scroll-snap 分页演示**（每页 100vh、目标 1920×1080）。单页长卷是连续滚动、无固定页高，这套不适用（长卷另有它的坑，见末尾）。

**核心公式**：
```
1080px = page-header(130) + slide-padding(40+40) + content(~870)
```

**典型 7 段叙事页高度预算**：
| 段 | 推荐 px | 极限收紧 px |
|---|---|---|
| 理念条（1–2 行） | 60–80 | 45–55 |
| X→Y 转向条（横向单行） | 45–60 | 35–45 |
| 主内容区（金字塔/数据/卡片/stepper） | 500–650 | 600–700 |
| 收尾/期待条 | 55–70 | 45–55 |
| gap × 3 | 50–70 | 30–40 |
| **总 content** | **710–930** | **755–895** |

**收紧 SOP（出现挤压/重叠时按顺序试）**：
1. 转向条改横向单行（省 40–50px）。
2. 理念/收尾条 padding 减 0.3rem（每段省 12–15px）。
3. 页面容器 gap 减 0.2rem（每 gap 省 5–8px）。
4. 内部卡片 padding 缩 0.2rem（每卡省 8–10px）。
5. 字号微降一档（中文正文 0.92rem → 0.86rem）。

**`min-height` 锁定防压扁**：某些视觉元素（图区/图标区）不能被压扁时，加 `min-height:150px`（或合适值），flex/grid 溢出时它们保持原尺寸，压力由其他可压缩元素吸收。

**🔴 必须留 60–100px buffer**：
- headless 渲染 ≠ 真实浏览器渲染（字号 clamp 取值不同、DPI 缩放、字体回退、line-height 各有差异）。
- 自动化检测 0 溢出 **≠** 视觉无重叠。**"检测通过"是必要条件不是充分条件。**
- **宁可内容稍紧凑也不要刚好装满**：把 content 高度目标控制在 900–950px（留 50–80px buffer 给跨浏览器差异）。**要"装舒服"，不要"挤进去"。**

**三件套溢出检测（自动化验证时必须都做）**：
1. **bbox 检测**：`getBoundingClientRect()` 比子元素 bottom 与父边界——但**被 `overflow:hidden` 切掉的内容 bbox 仍在边界内，抓不到**。
2. **scrollHeight 真溢出**：`el.scrollHeight - el.clientHeight > 0`——包含被切掉的真实高度，抓 bbox 的盲区。阈值：≤30px 视为盒模型 quirk，>30px 是真溢出必修。修 grid 撑大用 `grid-template-rows: minmax(0,1fr)` + 子元素 `min-height:0; overflow:hidden`。
3. **absolute footer 重叠**：`position:absolute` 的页脚脱离文档流，内容向下延伸会与它视觉重叠，但**前两种检测都抓不到**。检测内容最低 bottom vs footer top，>2px 即侵入。修法：给溢出页内容容器加 `padding-bottom`（比缩字号有效——缩字号会被 flex 兄弟吸收、总高不变）。

**装饰性伪元素的溢出伪报判别**：`::before/::after` 放的超边界装饰（水印数字/装饰圆环）会被 `overflow:hidden` 裁掉，是**设计意图**，但被算成溢出。判别口诀：**溢出量恒定**（同类卡片全同一个数字）= 装饰伪元素、放行；**溢出量各不相同且随文字长度变化** = 真内容被切、必修。

## 7. 动画编排原则

**核心判断**：**编排式 > 零散式**。一次整齐的 stagger reveal，胜过一堆散落的微交互。

- **入场**：`.reveal` 类初始 `opacity:0; transform:translateY(30px)`，进视口切 `.visible` 时 transition。
- **子元素 stagger**：delay 0.1s ~ 0.4s 递增（复杂页可分 8 档 0.10s→0.94s，按元素重要性配 `.blur-in`/`.scale-in` 子类型）。
- **触发**：Intersection Observer（滑入视口时），CSS-only 优先，JS 只用于导航。
- **动画类型**：Fade+SlideUp（0.6s, translateY 30px）/ Scale In（0.6s, scale 0.9→1）/ Blur In（0.8s, blur 10px→0）。

**工程坑（会导致"截图全黑/动画不触发"）**：
- 🔴 **用 DOMContentLoaded 启动，不要 window.load**：多字体家族时 `window.load` 要等所有字体加载完（叠加 networkidle 可达 4–6 秒），首屏动画迟迟不触发。判断：`document.readyState === 'loading' ? 监听 DOMContentLoaded : 立即启动`。
- 🔴 **图表类元素每次 activate 时 dispose + 延迟（~460ms）重新 init**，确保滚回来动画重播、不失去交互感。
- 🔴 **自动化截图不会触发 IntersectionObserver**：headless 用 `scrollIntoView` 滚过去**不切 active**，reveal 内容全是 `opacity:0`，导致"检测 0 溢出 = 假阳性"。截图前必须 evaluate 强制切 active：
  ```js
  slides.forEach((s, j) => s.classList.toggle('active', j === i));
  slides[i].scrollIntoView({behavior:'instant'});
  // 然后 sleep ~2s 让 transition + delay 跑完
  ```
- **`prefers-reduced-motion` 支持**：给不能承受动画的用户降级。

## 8. CSS 类名冲突陷阱（长项目多页共用前缀）

**症状**：长项目（10+ 页）多页用同名 class 前缀（`.fw-*` / `.action-*` / `.card-*`），后定义的 CSS 覆盖前定义的，**视觉上前页元素“位置乱了/尺寸变了”**——发现“位置乱了”时第一个要查的。

**排查**：
```bash
grep -nE "^\.fw-(node|center) \{" your.html   # 同名 CSS 是否多次定义
grep -nE 'class="fw-(node|center)' your.html   # HTML 哪几处在用
```

**修复（两选一）**：
1. 容器选择器限定：`.flywheel .fw-node {}` / `.flywheel-mini .fw-node {}`。
2. 独立前缀：新页改 `.p3-fw-*`。

**预防铁律**：**新页要复用现有视觉模板（stepper/卡片/环形图）前，先 grep 已有 class 名**，确认是新建 namespace 还是复用。做过"容器作用域批量配色"后，所有状态类（`.hot`/`.active`/`.warn`）都要带同级或更高作用域前缀，否则被压掉 background 变不可读（这类 bug 不报错、自动化检测不出，只能 Read 截图发现）。

**flex/grid 打散富文本坑（已反复复发，升级为铁律）**：**凡是"小圆点/小标签 + 一段含 `<b>/<em>/<a>` 的富文本"，一律不用 flex/grid，用 `position:relative` + `::before` 绝对定位**。因为 flex/grid 容器里每个子元素 + 每段匿名文本节点都是独立 item，富文本会被切成 N 个 item 各自换行，视觉上变成多列窄条甚至逐字竖排。判别：写下 `display:grid|flex` 后立刻数直接子节点——正文里有内联标签、item 数 >2 就必错。这类 bug 自动化全绿，只能 Read 截图发现。

# 第二部分 · 汇报设计（方法论层）

## 1. 语境识别（决定布局族）

**最关键的第一步**：材料的目标语境决定布局选择，三种语境不能混。

| 语境 | 角色 | 适配布局 | 错位反例 |
|---|---|---|---|
| **议题型**（向上级/平级提诉求） | "恳请支持" | icon-duo / compare-table / dual-path / tier | 给对方汇报成果 ❌ |
| **工作汇报型**（汇报成果） | "已完成 / 在做 / 计划" | dashboard / progress-cards / chart-duo / milestone | 给同级提诉求 ❌ |
| **应答型**（对方问你答） | 左口播 + 右备问 Q&A | 双栏段落 + 备问材料 | 用 bullet 要点 ❌ |

**自检问题**：动手前先问"**这是给谁看 → 他想从我这拿到什么？**"——汇报型的诉求口吻、议题型的进度条、应答型的图标，都是错位。说不清就问，不要凭感觉。

**Plan 状态不能编进度**：未启动事项就是 0%（或干脆不显示进度条），不能给"计划中"的事塞 5–20% 进度——看的人会以为已经做了一部分。metric 用定性词（"下季度启动"/"首批试点"）替代百分比。

**没图别留占位**：没有真实图片就**降级到无图布局**，不要用 placeholder 占位框（比纯文字更丑）。图片策略必须**排版前前置决策**——三选一：有业务图按有图规划 / 无图但需生成则先列清单生成再设计 / 只有文字就走"文字+设计"（用形状/色块/渐变/大数字/图标/数据可视化撑满，绝不为不存在的图留空位）。

## 2. 业务角度 vs 周报角度（达成了什么 ≠ 做了什么）

**判断**：汇报型材料（年中/年终总结、述职、高层汇报）最大的坑，是把"做了什么过程动作"当成"达成了什么工作"。

| ❌ 周报角度（过程动作） | ✅ 业务角度（实质成果） |
|---|---|
| 完成 X 材料整理 | 通过 X 同步 Y 进展 / 形成 Z 共识 |
| 明确三大核心诉求 | 就 X/Y/Z 与对方开展一轮沟通 |
| 围绕"从 A 到 B"形成完整材料 | 推动 A/B 转向落地 |
| 完成需求梳理 + 方案讨论 | 推动 X 立项 / 启动开发 |

**核心区别**：业务角度关注**达成了什么实质 / 沟通了什么内容 / 形成什么共识 / 推进了什么决策**；周报角度只关注**做了什么动作（写了什么、整理了什么、明确了什么）**。

**判别口诀**：
- 触发词警觉 ⚠️：完成材料 / 明确诉求 / 围绕主题 / 做出梳理 / 形成方案 / 推进筹备 → 多半是周报角度，重写。
- 重写公式：把"做的动作"换成"达成的实质"。
- 适用范围：年中/年终总结、述职、决策汇报、高层汇报。**不适用**：周报、日报、进展 status update（这些本就该报过程动作）。

**配套过滤**（哪些内容该上、该图、该删）：
| 类型 | 处理 |
|---|---|
| 创新型/有亮点的 | **详写**，单独成页 |
| 日常机制（每天都在做的） | **不报**——每天做的不算成绩 |
| 会议本身的准备工作 | **不报**——在会上讲是冗余 |
| 已是常识/现状 | 不报 |
| 数据型成果（收入/占比/增长） | **图表化**——列表不够冲击 |

**自检**："这条内容拿掉，会不会让汇报失去什么？"不会就删。

**措辞铁律**（不确定的事不能说死）：需要别人配合才能落地的动作 → 用"沟通推进 / 协调 / 探索"，不写"将上线 / 已确定"（说死会变成"立军令状但办不到"）。自己主导用"完成/落地/推进"，别人主导自己配合用"配合/协同 X 开展"。

## 3. 内容性格化版式 4 步法（防千篇一律）

**核心问题**：多章节/多支柱材料默认易写成"1 个模板套所有"——4 个章节每页都是"理念条+数据+卡片"，读者扫一眼觉得重复，记不住任何一页的差异。**版式 = 表达力的载体，不是装内容的盒子。**

### Step 1 · 识别章节性格
每个章节用 **1 个动词或名词**概括"它本质在表达什么" = 性格关键词。按性格选视觉语言：

| 内容性格 | 适配版式 | 视觉锚 |
|---|---|---|
| 结构性问题 / 层级 / 优先级 | 金字塔 / 漏斗 / 阶梯 | 3 层梯形 width 递减 |
| 具象产品列表 / 案例集 | 产品矩阵 | 3–5 张图卡 + 数据 + 短文 |
| 情感叙事 / 服务温度 | 场景叙事 | 大场景图 + overlay 文字 |
| 系统能力 / 平台架构 | 合作矩阵 + 能力图 | 左伙伴行 + 右能力模块 |
| 流程链条 / 因果递进 | 叙事 stepper | 顶部步骤条 + 长卡 + 桥接箭头 |
| 对比反转 / 现状→目标 | 左右双栏 + 中间转向 | 左 issue + 中→ + 右 shift |
| 数据 vs 数据 / 横向对比 | KPI 卡网格 / 柱形图 | 2×3 等宽卡 / 簇状柱 |

### Step 2 · 测试问题（防同质化）
自问："**如果这个章节只能用一张图说清楚，会是什么图？**"
- ✅ N 个章节给出 N 个不同回答 → 性格化有意义，进 Step 3。
- ⚠️ 2–3 个回答相同 → 只对差异化的章节性格化，相同性格用同一版式。
- ❌ 全部回答"图表"或"卡片列表" → 维度不够性格，统一版式即可，别硬加差异。

### Step 3 · 保留通用骨架，性格在主战场
| 元素 | 处理 |
|---|---|
| 页眉（编号+标题+副标） | **维持统一**（保持节奏） |
| 理念条 | **维持统一**（阅读锚点） |
| 收尾/总结条 | **维持统一**（收尾节奏） |
| **中段主战场（数据+动作+视觉锚）** | **性格表达**——性格化的主战场 |
| 页码/底部品牌条 | **维持统一** |

**为什么**：通用骨架（首尾）让"页与页有节奏"，主战场性格化让"每页有记忆点"，两者缺一不可。

### Step 4 · 3 检查（防自欺）
1. **内容完整性**（最重要）：原文核心内容（重点工作/行动项/决策点）有没有被视觉装饰替换掉？（见下方"视觉替代内容陷阱"）——被问"重点工作几项"必须能从材料里直接读出来。
2. **读者第一反应差异化**：每个章节扫一眼形成的"第一印象关键词"是否各不同？（同 = 性格化失败）
3. **视觉重心错位**：N 个章节并排看，视觉密度/重心位置是否各有特色？（顶部/中部/左侧/右侧 各不同）

### 🔴 何时**不该**性格化
不是所有材料都该性格化，以下场景**统一版式反而对**：
| 场景 | 为什么 |
|---|---|
| 章节是并列同级关系（如 N 个同维度 KPI） | 同级元素差异性格 = 制造混乱 |
| 章节字数差异大（50 字 vs 500 字） | 字数本身定形态，不需硬塞不同版式 |
| 严肃汇报 / 对外路演 / 投资人 deck | 保守稳定 > 视觉创新 |
| 时间紧张（<4 小时出稿） | 性格化每章单独设计，耗时 2–3 倍 |
| 章节数量 ≥ 6 个 | 风格碎片化反伤整体性 |

**适用范围**：章节 3–5 个 + 内容性格本身差异化 + 时间充裕 + 受众对视觉敏感。

### 🔴🔴 配套铁律 · "用视觉替代内容"陷阱
做性格化/视觉升级时，**最危险的错**是把原文核心内容（重点工作清单/行动项/决策点）用视觉装饰（产品图/架构图/能力卡）整体替换掉——自以为加成，实为减法。**产品图 ≠ 重点工作，能力图 ≠ 行动项；视觉只是承载，内容才是主体。**

交付前**必走自检**：
1. 打开原文 → 显式列出"重点工作/行动项/待决项" N 项。
2. 打开产出 → 逐项检查是否**有独立卡片或显式段落**（不能"装进图里"或"嵌进描述里"）。
3. 发现被视觉化替代 → **加回独立卡片**，让视觉作佐证而非替身。
4. 综合分基于"内容覆盖率 N/N"，不是"视觉好看度"。

版式建议（N 项行动 + 视觉锚）：上=数据带 / 中=N 个行动卡（**必有**，内容主体）/ 下=视觉锚（佐证）/ 底=总结条。

## 4. 总结页三件套（禁止与前文重复）

**判断**：总结页最常见的坑，是把前面 N 个章节的关键字重新罗列一遍。观众读到这里已经看了全部章节，再罗列 = 重合度高、信息密度低，浪费宝贵的"总结记忆位"。**总结页内容能在前文找到 ≥70% = 必须重写。**

**总结页三件套（汇报型通用）**：
1. **单一数字目标**：把 N 个章节的成果**收敛到一两个能记住的数字**（如"当前占比 X% → 目标 Y%"）。
2. **外部对照引入**：把自己的数据和**外部参照**（同类对象/行业基准/历史最佳）并列，给观众判断锚点。
3. **学习姿态收尾**：明确表达"向 X 学习 / 希望多交流"——降低汇报锋芒，给协同留接口。

**配套视觉**：核心目标 banner 用主题双色渐变大块（视觉权重最大）；对照表用 3 行表格，自身行用高亮底色标识；学习姿态条用中性渐变条。

**判别口诀**：总结页内容能在前 N-1 页找到 ≥70%？= 重写。

## 5. 宏观叙事骨架（核心隐喻贯穿全篇）

**定位**：前面几条管单页/组件/视觉，本条管**整份材料作为一个故事的宏观骨架**——这是"叙事结构和逻辑明晰"的真正来源。

**触发条件**：多页（≥8 页）成体系的工作汇报/战略汇报/方案路演；内容有多个并列模块需统一编排；目标是"让听众跟着一条线走完"。**不适用**：单页长卷自读材料、纯数据看板、应答型 Q&A。

### 宏观骨架 4 要素（缺一则散）
**① 核心隐喻贯穿全篇**——一个隐喻统领所有页，不是各页各讲各的。
- 隐喻要选"能同时表达问题 + 解法"的。例如"收窄型漏斗 → 循环型飞轮"这类隐喻：漏斗是问题态（越往后越窄），飞轮是解法态（循环驱动），一个隐喻把"为什么变 + 变成什么"都说了。
- 封面、命题页、总结页都回扣这个隐喻，形成记忆锚。

**② 总分总三段式**——提出 → 展开 → 收束。
| 段 | 页 | 角色 |
|---|---|---|
| **总（提出）** | 命题页 | 抛核心命题 + 隐喻转向 + 预告下面分几支 |
| **分（展开）** | N 个支柱页 | 每支独立成段，走统一节奏 |
| **总（收束）** | 总结页 | 收敛到单一数字目标 + 外部对标 + 学习姿态 |
| 首尾 | 封面 / 致谢 | 隐喻亮相 / 情绪收尾 |

**③ 分支之间是递进闭环，不是平行罗列**——让听众感到"这几支是一个圈/一条链"。
- **检验**：把支柱顺序打乱，逻辑会不会坏？会坏 = 有递进（好）；不会坏 = 平行罗列（弱）。
- 天然平行（无递进）就人为赋予一条线索（时间/优先级/价值链/受众旅程），别让它散着。

**④ 每个分支统一节奏**——页与页之间有可预期的韵律。

### 🔴 支柱页标准架构（每个"分"页套同一个模子）
```
┌────────────────────────────────────┐
│ page-header: 序号 + 支柱主张 + 英文副标  │
├────────────────────────────────────┤
│ ① 理念条：这个支柱"为什么"，1–2 句，左强调竖条 │  ← problem 前置
├────────────────────────────────────┤
│ ② 现存→转向条：⚠现存问题 → 🎯转向，单行紧凑    │  ← shift
├────────────────────────────────────┤
│ ③ 重点工作主体（性格化版式，这页主战场）        │  ← action
└────────────────────────────────────┘
```
**三段逻辑 = problem → shift → action**：先讲理念（为什么），再点破现存问题+转向（从哪到哪），最后给重点工作（怎么做）。每个支柱页都这样，**听众第二页起就能预判节奏，认知负荷降到最低**。

**收尾条不是必须**：当它变成"为了对称而对称"的空话就删。节奏统一指的是"理念→转向→工作"三段主体，不是强制每页都加尾巴。

### 动手前自检（多页成体系汇报时）
```
□ 核心隐喻选好了吗？它能同时表达"问题态"和"解法态"吗？
□ 命题页(总)→支柱页(分)→总结页(总) 三段齐全吗？
□ 各支柱之间是递进闭环还是平行罗列？打乱顺序会坏吗？
□ 每个支柱页都走"理念→转向→工作"同一节奏吗？
□ 总结页是收敛到单一目标，还是又把前文罗列一遍？
```

### 配套 · 新发现是"叠加副线"还是"替换主线"
听众/用户在已有主线叙事里抛出一个有冲击力的新发现时，**默认"副线叠加"，除非明确说"换主线"**。
| 信号 | 判断 |
|---|---|
| "两层架构"/"作为支线"/"不要当核心" | **副线叠加**——保留原主线，新发现明显存在但不抢戏 |
| "换个主题"/"核心命题改成 X"/"不要再讲原来的 Y" | **替换主线**——可大改 |
| 没明说，只给了新数据/新视角 | **默认副线叠加**（保守，避免推翻原骨架） |

视觉权重：主线占版面 60–70%+、主品牌色、页面主体；副线占 5–15%、克制的警示色、单条横向（底部/顶部）、明确标"副线"。

## 6. "关系图 ≠ 矩阵"（graph vs matrix 判断）

**反模式**：听到"做一个关系图说明 X/Y/Z 的关系"，第一反应做成 2×N 矩阵/表格——**信息完整但本质是 table 不是 graph**。根因：把"关系"理解成"维度交叉"（矩阵），而非"实体间的关联/归属/流向"（graph）。

| 场景 | 该用什么 |
|---|---|
| **关系**（实体 A 来自/属于/流向 实体 B） | **graph**：节点 + 连线（SVG 或图表库 graph） |
| **对比**（X/Y/Z 在维度上的差异） | matrix / table / 雷达图 |
| **覆盖**（X 在 A/B/C 维度能否做到） | 矩阵 + ✓△✗ |
| **位置**（X 在 2D 维度的坐标） | 散点图 / 2×2 矩阵 |
| **演进**（从 X 到 Y 到 Z） | timeline / tier-diagram |

**判断关键词**：
- "关系图" / "展示 X 和 Y 的关系" / "X 来自/归属/流向" → **节点-连线 graph**。
- "对比/差异/区别" → matrix。
- "X 在 Y/Z 维度位置" → 2×N 矩阵/散点。
- "覆盖/能否/是否" → ✓△✗ 矩阵。

**关系图 SVG 实现 pattern**（可复用）：容器 CSS Grid 分列（左维度节点/中实体/右维度）；节点用 div/card；SVG 在底层（`position:absolute; z-index:1; viewBox="0 0 100 100"; preserveAspectRatio="none"`）画连线，节点 `z-index:2` 浮在线上；连线百分比坐标对应节点中心，`vector-effect:non-scaling-stroke` 让线宽不随容器拉伸；虚实区分关系性质 + 底部 legend。

**反向自检**：动手前问"用户要 graph（关系流向）还是 matrix（维度对比）？"——回答不清就**主动问**（"您要节点-连线的图，还是对照矩阵的表？"），不要默认表格。

**进阶 · 讲框架必有结构图**：只要材料出现"N 条主线 / M 个方向 / 若干需求项"这种**多层级分类体系**，就必须有一张能看出**层级归属**的图（并排卡片只表达"并列"，表达不了"归属与层级"）。结构图最低要求（缺一不可）：① 有根节点；② 有连接线可追溯归属；③ 层级画到底（到读者关心的最小颗粒，不要画到第二层就停）；④ 图上标出易混点；⑤ 全图只留一个高亮点。纯 CSS 实现：根节点 div 居中 → 一个高 30–44px 的连接层（1 条竖线 + 1 条横线 `left:16.6%;right:16.6%` 对齐三等分列中心 + 3 条短竖线 `left:16.6%/50%/83.4%`）→ 下接三列 grid，窄屏 `@media` 把横/短竖线 `display:none` 退化为纵向堆叠。（N 列时第 1 列中心 = `100/(2N)`%。）

**表达"支撑关系"用纵向加箭头，表达"二选一差异"用左右并排**：并排布局天然表达"并列"，要表达"谁支撑谁"必须让布局本身有方向（纵向堆叠 + 行间箭头 + **箭头上写清"为什么下一环需要上一环"**——只有箭头没有理由等于装饰）；但表达"保持现状 vs 更换"这类对照关系时，左右并排恰恰最优（风险差异是"看出来"的，不是"读出来"的）。

## 7. 元素数量变化必触发布局重设

**反模式**：原本 5 卡横排，要求改 4 项 → 直接删掉一个卡留 4 个。

**为什么错**：5 卡和 4 卡的排版逻辑不同——5 卡只能横排且每张偏窄；4 卡更适合 2×2 网格、可做更大的卡，视觉权重不一样。**简单删除 = 把原有错位继承下来 + 浪费了"少元素带来的视觉松弛感"。**

**触发条件**：N → M 元素（N ≠ M）时，必须问自己"**M 项在新页面上的最佳排版是什么**"，不能假设"反正只是少了一个"。

**正例**：5 卡横排改 4 项时 → 改成 2×2 大卡（卡片更大、顶部 4 步 stepper、大水印序号做背景，视觉松弛）。

**判别口诀**：元素数量变了 → 布局必须重新想。用户说"那排版要和 X 项不一样了"= 这条触发了。

**配套**：同主题多页先尝试合并再判断（同主题先合到 1 页用网格/对照表，合不下再拆，拆要按真实差异如"已上线 vs 计划中"，不是数量分批）；内容少时"大片留白比挤更丑"——优先补充真实内容，其次换布局（如带图 progress-cards → split-layout 双卡），最后合并页。

## 附 · 单页长卷（非 scroll-snap）的差异

单页长卷是连续滚动、无固定页高、无页码——上面的"1080px 高度预算 / 页码同步"**不适用**，但有它自己的判断点：
- **等高多列里某列内容远少于其他列 = 大片留白**：优先**补充真实层级内容**（把条目内部的层级/阶段拆成小标签行），而非给短列加 `justify-content:center`（空白还在，只是位置变了）。
- **交付默认要求**：零外部依赖（系统字体栈 + 内嵌 JS，不引 CDN/Google Fonts）、正文按大屏 +25% 档、顶部滚动进度条 + 右侧章节导航点、`@media print` 隐藏导航并强制显示动画元素。
- **详述降级用 `<details>`**：默认收起、主讲时点开，但收起态要放摘要（不能空白）；必须配 `beforeprint` 钩子把所有 `<details>` 置 `open=true`，否则导 PDF 丢内容。
