# 配色科学指南 · color-guide

> 这篇是 DeckSmith 的**配色推导手册**：把"凭感觉选色"换成"照数值推导"。
> **何时读**：走到 `SKILL.md` 的 **Step 5 · 配色**，且不用预设、要**从一两个品牌色推导整套色板**时；或预设色不够、需要理解某条配色规则背后的科学时。

## 0. 一句话心法

**多色要协调 = 只让色相（H）变，把饱和度（S）和明度（L）钉死。** 记不住别的就记这句——第 2 节展开。

配色不是审美天赋，是可推导的工程：确定主色相 → 用色相环关系推辅色 → 用等明度等饱和锁协调 → 用 60-30-10 分配面积 → 用图底关系让卡片浮出。下面每节都给"怎么做"的可操作准则。

---

## 1. 色相环六大配色方案

先确定主色的色相角 H（0–360°），再用色相环上的**角度距离**推算辅色和强调色。

| 方案 | 色相环距离 | 效果 | 适用场景 |
|------|----------|------|---------|
| 单色 / 同类色（Monochromatic） | 0°~60° | 统一协调 | 同主题内做层级区分 |
| 邻近色（Analogous） | 60°~90° | 柔和丰富 | 卡片差异化、图表多系列 |
| 对比色 | 120°~180° | 强烈对比 | 突出重点 |
| 互补色（Complementary） | 180° | 最强对比 | 关键数据强调（如蓝 + 橙） |
| 分裂互补（Split-Complementary） | 180° 两侧各偏 30° | 高对比但柔和 | 三色方案 |
| 三角色（Triadic） | 等距 120° | 活泼平衡 | 三分类数据 |
| （四角色 / Tetradic） | 两组互补，间隔 90° | 丰富但难控 | 多分类，须一色主导其余退后 |

**为什么**：色相环上的角度关系决定搭配是否和谐。随意选色会"看着不舒服但说不出哪里不对"——那多半是角度关系乱了。

**怎么做**：
1. 先定主色 H（例：蓝 H=215）。
2. 要一个强调色 → 取互补 H≈35（180° 附近的暖色区），或分裂互补 H≈185±30。
3. 要三系列数据 → 三角色 H=215 / 335 / 95，或退一步用邻近色 H=215 / 245 / 185（更柔和）。
4. 四角色慎用：四个色相跨度太大，必须让一个绝对主导、其余降饱和退后，否则花。

## 2. HSL 等明度等饱和配色（最核心技巧）

**法则：多种颜色要协调 → 只变色相（H），保持饱和度（S）和明度（L）不变。**

| 要素 | 配色作用 |
|------|---------|
| **H 色相** | 变化色相创造多色区分 |
| **S 饱和度** | **低饱和 = 高级感**，高饱和 = 廉价感 |
| **L 明度** | **等明度 = 视觉等重 = 协调** |

**高级感公式：低饱和 + 中低明度 + 少量高饱和强调。**

实操参数（可直接抄）：
- **图表多色**：固定 `S=60% L=55%`，只变 H → 天然协调。
- **两色对比**：蓝 `H=215 S=60% L=55%` + 暖 `H=30 S=60% L=55%` → 等饱和等明度，两色视觉等重。
- **卡片差异化**：固定 `S=25% L=14%`，H 变 210 / 140 / 30 / 280 → 深蓝 / 深绿 / 深棕 / 深紫，各不相同又协调。

**为什么**：**饱和度不一致是"配色看着不协调"的第一大原因。** 举例，若蓝色 S=65% 而橙色 S=81%，差了 16%，橙色就会在视觉上"太跳"。

**怎么做（硬性自检）**：每次选色先写出每个色的 HSL 值，**检查所有并列色的 S 差距 < 10%、L 差距 < 10%**。超了就往中间拉平。

---

## 3. OKLCH 感知均匀色彩模型

HSL 的明度不准——同为 `L=50%` 的蓝色，看起来比黄色暗很多。**OKLCH（Lightness / Chroma / Hue）是感知均匀的**：

- 同 L 值的颜色，人眼看起来**真的**一样亮。
- 固定 L 和 C、只变 H → 比 HSL 更天然协调（不会出现"某个色相莫名发暗/发亮"）。
- CSS 原生支持：`oklch(65% 0.15 215)`（L=65% Chroma=0.15 Hue=215）。

**怎么做**：需要一组"视觉等亮"的多色板（尤其图表系列色、并列卡片色）时，优先用 OKLCH 而非 HSL——固定 L 和 C 只扫 H。可用在线工具（如 oklch.fyi）取值，再转 CSS。HSL 适合快速手推，OKLCH 适合要求"绝对等亮"的场合。

## 4. 60-30-10 法则

面积分配决定画面是"稳"还是"花"：

- **60% 主色**：背景 / 大面积 → 通常是深色或浅色基底。
- **30% 辅色**：卡片 / 面板 / 结构元素 → 主色家族的中间调。
- **10% 强调色**：关键数据 / CTA / 一两个必须被看到的数字 → 高饱和的互补色（橙 / 金 / 信号色）。

**为什么**：强调色一旦超过 10%（比如同时出现在编号、数字、图表每根柱子上），画面立刻"花"。强调色的力量来自稀缺。

**怎么做**：
- 强调色**只**用在最关键的 1–2 个数字 / 一个 CTA 上。
- 次要的编号、标签改用**降饱和版**或金/中性色，不要跟主强调色抢。
- 图表柱子用主色家族的降饱和版，别整排上强调色。

## 5. 暗色模式配色规则

暗色不是"把亮色反过来"，有独立规则：

1. **不用纯黑 `#000000` 背景** → 用深灰 `#0D121B`~`#1A202C`（带一点蓝/主色调）。
2. **不用纯白 `#FFFFFF` 文字** → 用柔白 `#E2E5E8`（带微量主色调，如 `HSL 215/10%/90%`）。
3. **降低饱和度**：暗背景下高饱和色刺眼，把强调色 S 降到 **55–65%**。
4. **中性色带主色调**：灰色不用纯灰，注入主色 H（如 H=215 的蓝调灰），整体更统一。
5. **对比度达标**：正文 ≥ 4.5:1，大字 ≥ 3:1（WCAG AA）。

**Material 暗色层级原则**：层级越高的表面越亮（等效于叠加 5%→16% 的白色 overlay）。**用同色系不同明度表达层级**，不要用不同色相表达层级。

## 6. 底色与元素的色温一致性（🔴 最关键的教训）

**法则：暖色元素必须配暖底色，冷色元素必须配冷底色。底色和元素色温对撞 = 不高级。**

| ❌ 错误 | ✅ 正确 |
|------|------|
| 冷蓝底（H=220） + 暖金元素（H=30） = 190° 色温对撞 | 暖黑底（H=40） + 暖金元素（H=30） = 10° 同温度 |
| 底色 S=35%（明显偏蓝，抢色温） | 底色 S=20%（接近灰，不抢色温） |

**为什么**：观察大量高级配色案例可发现——高级配色的**底色和元素色相差通常只有 15–28°**；而"看着脏 / 不高级"的配色，底色和元素常差到 180° 以上（色温正面对撞）。

**怎么做（4 步）**：
1. 确定元素主色相（如金色 H=30）。
2. 底色色相控制在主色 **±30°** 以内（如 H=0–60 的暖色区）。
3. 底色饱和度 **≤ 20%**（近灰，不抢戏）。
4. 或者干脆用中性黑（S < 10%），让底色**完全退出**色温竞争。

## 7. 卡片"浮出"背景的具体参数（图底关系 Figure-Ground）

卡片跟背景明度太接近，就会"融进背景、分不出来、显脏"。让它**立在背景上**要靠明度差 + 可见边框 + 实色渐变。

**法则：卡片与背景明度差 ≥ 15%，边框可见度 ≥ 30% alpha。**

| 参数 | ❌ 融入背景 | ✅ 浮出背景 |
|------|-------------|-------------|
| 背景明度 | L=6% | L=6% |
| 卡片明度 | L=10%（只差 4%） | **L=22%（差 16%）** |
| 边框 | 白色 10% alpha（看不见） | 主色调 `#7F684C` **40% alpha**（清晰可见） |
| 阴影 | blur=15 alpha=50% | blur=20 dist=8 **alpha=60%** |
| 卡片填充 | 半透明黑 60%（发灰发脏） | **实色渐变** `#3E3831→#2A2520`（上亮下暗） |

**怎么做**：卡片用**实色渐变**（L=22% → L=15%，上亮下暗）而不是半透明黑叠加；边框用主色调、**≥ 30% alpha** 才看得见；配一层稍重的阴影（blur=20 / dist=8 / alpha=60%）。三者叠加卡片才会"立起来像一枚扣子"，而不是印在纸上的水印。

## 8. 三种高级配色模式

分析大量高级配色案例，归纳出三种可套用的模式。**关键发现：高级配色的饱和度大多落在 15–45%**——60% 已经偏高。

**模式一 · 同色系渐变（最高级）**
色相 ±15° 基本不变，饱和度 spread 仅 7–18%，靠**明度跨度**（L=20% → 96%）创造层次。
→ 高级感的本质：**不换颜色，只换明暗。**

**模式二 · 邻近色低饱和（莫兰迪风）**
邻近 30–60° 色相，饱和度压到 **4–25%**。
→ 统一的灰调让所有颜色自然融合，不打架。

**模式三 · 对比色克制（多色 / 五色方案）**
色相跨度大，但让**一个色绝对主导、其余退后**（退后的降饱和到 S=30% 左右）。
→ 黑金、蓝金这类风格属于此模式：金主导，蓝必须克制降饱和。

**怎么选**：要极致高级 / 商务 → 模式一；要柔和文艺 → 模式二；已有强对比双色（品牌蓝 + 品牌橙）→ 模式三，让其中一个退后。

## 9. 🔴 从两个 RGB 推导完整色板（10 步工作流）

**这是本文最有价值的可操作方法论。** 给两个颜色（品牌主色 + 强调色），产出 16–20 个角色色值的完整色板。

**输入**：两个 RGB 值（主色 + 强调色）。
**输出**：背景 / 卡片 / 4 级文字 / 主色家族 4 级 / 强调色家族 4 级 / wash 色，共 16–20 个角色。

**步骤**：
1. **转 HSL**：两个 RGB 各转 HSL，得到 `H1`（主色色相）、`S1`、`L1` 和 `H2`（强调色色相）、`S2`、`L2`。
2. **判色相关系**：算 `|H1 − H2|`，对照第 1 节判断是互补 / 邻近 / 三角 → 据此选第 8 节的配色模式。
3. **定基调**：暗色还是亮色 → 决定背景 L 值（**暗：6–8% / 亮：95–97%**）。
4. **推背景色**：`H=H1, S≤10%, L=基调值`（底色不抢色温，见第 6 节）。
5. **推卡片色**：同 `H=H1`，L 比背景**深/浅 6–16%**（浮出参数，见第 7 节；暗底则卡片更亮，亮底则卡片更暗或纯白）。
6. **推文字色（4 级）**：正文 `L=18–22%`（亮底）或 `L=88–92%`（暗底）；辅助 / 弱 / 极弱依次向背景方向递推（对比递减）。
7. **推主色家族（4 级）**：固定 `H1`，S 从高到低（原色 / 中 / 亮 / 浅），L 递增 → 原色 / 中调 / 亮调 / 浅调。
8. **推强调色家族（4 级）**：固定 `H2`，同第 7 步。
9. **追加 wash 色**：极浅底色，用于标签 / 色块填充 → `S=30–40%, L=90–94%`（每个家族各一个）。
10. **用 60-30-10 验证**：主色占 60%（正文 + 背景）、辅色占 30%（卡片 + 分隔）、强调占 10%（仅关键元素）。比例不对就回去调面积。

**亮色基调实测样例**（输入 `RGB(0,57,108)` 主蓝 + `RGB(255,125,35)` 强调橙）：

| 卡片面 | `#FFFFFF` → `#FAFBFC` | 纯白渐变 |

**两条从实战摔出来的铁律**（并列元素配色）：
- **并列同级卡片不要用不同底色**：多个等重卡片用蓝/绿/褐三种底色，既无语义逻辑、又在暗色下深浅不一显脏。**统一同一暗色**（如 `#1A2030`），靠内容区分而非颜色区分。
- **并列同级数字不要用不同颜色**：三个等重指标用三种颜色，暗示了不存在的重要性差异。**统一一个色**（如统一金色）。
- 元规则：设计并列元素前先问"**为什么这几个要用不同颜色？**"——答不出语义理由就统一。**没含义的颜色不如不用。**

## 10. 亮色基调的填充质感技法

**问题**：亮色背景 + 大留白 = 空旷没质感。暗色版靠 grain 纹理 + 渐变光晕填充，这些在亮色上不适用。

**解法——6 种亮色填充元素（CSS 直接抄）**：

| 技法 | CSS 实现 | 效果 |
|------|---------|------|
| 点阵底纹 | `radial-gradient(circle at 1px 1px, rgba(主色,0.04) 1px, transparent 0); background-size: 28px 28px;` | 全页微纹理，消除纯白平面感 |
| 双色渐变光晕 | `radial-gradient(ellipse at 0% 0%, rgba(主色,0.05)...)` + `radial-gradient(ellipse at 100% 100%, rgba(强调色,0.05)...)` | 左上 / 右下有色彩倾向 |
| 大数字水印 | 超大字号（16–28rem） + `rgba(主色, 0.025)` | 填充封面大片留白 |
| 装饰圆环 | `border-radius:50%` + `border:1.5px solid rgba(色,0.05–0.06)` | 多个不同大小散布 |
| 对角线条纹 | `linear-gradient(135deg, transparent 40%, rgba(主色,0.02) 40%, rgba(主色,0.02) 42%, transparent 42%)` | 右半部分几何感 |
| 脉冲光环动画 | `@keyframes pulse-ring { scale(1)→scale(1.15); opacity 0.4→0; }` | 给关键节点加呼吸感 |

**额外填充元素**：侧边全高渐变色带（5px）、侧边竖排旋转英文标签、卡片图标外圈虚线环（dashed border）、阶段性大数字指标（0% → 60% → 100%）。

**核心原则**：亮色基调的填充**不能靠加内容文字**，要靠**装饰性视觉元素**占据空间——颜色极浅（alpha **2–6%**）不抢注意力，但能消除空旷感。

## 11. 浅色 primary 的特殊处理（pl > 55% 时）

**问题**：用第 9 节的 10 步推色板时，如果 primary 本身就浅（如某浅黄棕主色 `#D4A373`，`L=64%`），按"固定 H 只变 L"推出的 primary_mid / bright 也会偏浅，导致卡片里用 `var(--primary-mid)` 的文字**对比度不够、几乎隐身**。

**修复法则（亮色 / 中性基调下，`pl` = primary 的 L，`ps` = primary 的 S）**：
1. **primary_mid 必须可读**：当 `pl > 55%` 时，不做常规推导，改为"**加饱和 + 减明度**"：
   `S = min(80, ps+10)`，`L = max(30, pl−30)`。
2. **text 不继承 primary hue**：当 `pl > 55%` 时，正文色用**中性 slate**（`H=220, S=15%`）而非 primary 的 hue——否则文字会被主色的浅化带偏、变淡。
3. **accent 标签文字用 accent_soft 而非 accent 本色**：如 `.tag.warm { color: var(--accent-soft); }`，因为 accent 本色在浅底上对比度往往不够。

**为什么**：这三条修好前后，浅主色方案会从"标签几乎隐身"变成"清晰可读"。

## 12. 风格维度轴匹配（tone / hue_family / saturation / contrast）

给用户选风格时，**不要让他从一堆主题名里挑**，而是让他选 **4 个维度轴**的取值，再匹配到最近的预设。

**4 个维度轴**：
- **tone（基调）**：dark / medium / light
- **hue_family（主色相族）**：warm / cool / neutral / mixed
- **saturation（饱和度）**：very_low / low / medium / high
- **contrast（对比度）**：low / medium / high

**匹配算法（距离矩阵加权）**：
```python
# 每个轴建一张距离矩阵：同类=0，相邻=1，远=2
# 各轴权重不同，加权求和取最小距离的预设
dist = TONE_DIST[user][preset]     * 2      # 基调影响最大
     + HUE_DIST[user][preset]      * 1.5    # 主色相次之
     + SAT_DIST[user][preset]      * 1      # 饱和度一般
     + CONTRAST_DIST[user][preset] * 1      # 对比度一般
```

**wildcard 支持**：允许某个轴填 `"any"`（不指定），只对填了的轴计距离——这样"只指定 暗 + 冷"的场景也能工作，不强迫用户填满四轴。

**怎么用**：DeckSmith 的预设（`presets/`，如 warm-gold-dark / blue-orange-light / ink-gradient / morandi-grey / forest-cream 等）都可标注这四轴的取值；用户表达出的调性 → 转成四轴 → 跑一遍加权距离 → 命中最近的预设。命中后仍不满意，再走第 9 节从品牌色定制。

## 13. 视觉自测必须补在技术测试之后

**问题**：自动化测试（如 playwright）8/8 全过——零 page error、零 console error、零溢出——但截图一看，浅色基调 + 小字的文字**几乎看不见**。

**根因**：技术测试只验证"**有没有错误**"，不验证"**看不看得清**"。对比度、色彩和谐、视觉层次都是**眼睛的事**，代码检测不到。

**怎么做**：
- 任何涉及配色 / 布局的产出，**自动化测试通过 ≠ 合格**。
- 必须**人眼过一遍关键截图**（特别是浅色基调 + 小字、深色叠深色的场景）。
- 发现视觉问题 → **回溯到推导算法 / CSS 规则层去修**（如第 11 节的 `pl>55%` 规则），**不要在 HTML 里打局部补丁**——补丁会让文件越改越碎。
